# Release Process

We follow semantic versioning (MAJOR.MINOR.PATCH). Use tags to trigger CI release workflows.

1. Prepare release
- Update CHANGELOG.md with notable changes under the new version
- Bump version in pyproject.toml (and setup.cfg if needed)

2. Create tag and push
- git tag vX.Y.Z
- git push --tags

3. Release automation
- On tag push GitHub Actions will build and publish the container image and Python package (requires secrets: GHCR_PAT, PYPI_API_TOKEN)

4. Post-release
- Update website/docs (mkdocs is built in CI)
- Create release notes using the GitHub Release generated by workflow

Rollbacks
- Use image tags and helm rollback if needed. For DB rollbacks, use alembic downgrade with caution and backups.
